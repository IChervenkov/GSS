# Module Ownership Policy

Every top-level module must have an explicit ownership record.

## Required fields

- Primary owner
- Secondary owner / backup
- Scope
- Critical dependencies
- Critical user flows
- Change risks
- Minimum review requirement
- Operational dashboards / alerts to watch
- Runbooks linked

## Ownership default for current state

The system is currently operated primarily by a single engineer. These records are still useful because they define where responsibility lives and what must be reviewed when ownership expands later.
